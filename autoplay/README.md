# 公開情報だけで進める Mines 自動処理

## 組み込みと使い方

1. 元のゲームプロジェクトの `mines.c` を、このフォルダの `mines.c` に置き換え、同じディレクトリに `visible_solver.h` を置きます。元のファイルはバックアップしてください。
2. 元プロジェクトの通常の方法で再ビルドします。追加添付された `puzzles.h` と `grid.h` は同梱しています。ヘッダーを含む改造版全体のオブジェクト生成は成功しましたが、関連実装が不足するため、実行ファイル全体のリンクは未確認です。
3. プレイヤーが最初のマスを開きます。
4. ゲームの Solve（解く）を実行します。確定マスの開封・旗立て・再推論を自動で繰り返し、完成するか推論が止まるまで進めます。

追加の Python、外部サービス、ライブラリは不要です。従来の全答え表示を行う `solve_game` を置き換えています。実行結果は通常の O / PF コマンド列で反映されます。途中まで進んだ場合は盤面が更新され、次回 Solve を押しても確定手がなければ停止理由が表示されます。初手、終了済み、確定手なしの場合は英語のメッセージを返します。アニメーションや常駐ボットではなく、Solve 1回で連続処理する方式です。

## 判断に使う情報

`visible_solver.h` の `vs_next` は、公開された数字、公開された盤面の隣接関係、自分で証明した爆弾だけを受け取ります。内部の爆弾配列、乱数、盤面生成の情報、非公開の開始位置は受け取りません。総爆弾数も参照しません。初期の手動の旗・疑問符は未確定として扱います。誤った旗が安全マスにあれば、確定した時点で開きます。無関係な手動の旗を一括で消すことはしません。

推論は次の規則を繰り返します。

- 数字から既に証明済みの爆弾を引き、残りが0なら隣接する未確定マスは安全。
- 残りの爆弾数が未確定マス数と同じなら、すべて爆弾。
- 制約 A のマス集合が B に含まれる場合、B−A と爆弾数の差に上の規則を適用。

安全と証明したマスは元の `open_square` で開きます。この通常のゲーム処理が内部配置を使って数字や勝敗を算出することはありますが、判断部は開封後に公開される結果だけを次の推論に使用します。盤面を変更する生成用の perturbation や、全答え表示の S コマンドは自動処理から呼びません。

推測・確率選択は行いません。この規則で解けない盤面や、さらに高度な論理が必要な局面では停止します。全盤面の完全解答は保証しません。最大16隣接の盤面に対応し、正方形以外も元ゲームの隣接表とタイル番号を使います。

## 検証

このフォルダで以下を実行します。

```sh
cc -std=c99 -Wall -Wextra -Werror test_solver.c -o /tmp/test_visible_solver
/tmp/test_visible_solver
cc -std=c99 -Wall -Wextra -Werror test_integration.c -o /tmp/test_mines_integration
/tmp/test_mines_integration
```

- 3×3 の全爆弾配置と安全マス公開状態、計19,683ケースで、25,658回の推論の正当性を確認。
- 部分集合の差による安全／爆弾判定、曖昧な局面での停止、矛盾の検出を確認。
- 結合テストはゲーム型の最小スタブと、元コードから抽出した初手後の開封処理を使用。誤った手動の旗を無視し、通常コマンド列を再生して勝利できること、初手は停止すること、入力状態を変更しないことを確認。
- AddressSanitizer / UndefinedBehaviorSanitizer 付きでも成功。実行環境の ptrace 制限により LeakSanitizer は無効化して実施。

追加の `puzzles.h` と `grid.h` を使用し、`cc -std=c99 -c mines.c -o /tmp/mines-autoplay.o` は成功しました。`-Wall -Wextra` での構文確認もエラーなしで、既存コードの未使用引数や符号比較の警告があります。
