# Mines 自動処理 — プレイヤーと同じ情報で解く

マインスイーパーの C ソースを改造し、プレイヤーに公開されている情報だけから安全マスと爆弾を推論して、自動で開封・旗立てを行います。最初のマスを手動で開き、ゲームの **Solve（解く）** を実行すると、確定手がなくなるかゲームが完成するまで連続処理します。

## 特徴

- 判断に使うのは、開いたマスの数字、盤面の隣接関係、自動処理自身が証明した爆弾だけ。
- 内部の爆弾配置・乱数・生成情報・非公開の開始位置は推論部に渡しません。総爆弾数も使いません。
- 手動の旗・疑問符は未確定として扱い、誤った旗を根拠に開封しません。
- 数字と残りの未確定マス数による推論、および隣接集合の包含関係による差分推論を繰り返します。
- 推測は行わず、確定手が見つからなければ停止します。すべての盤面を解けるわけではありません。
- Python や外部サービスは不要です。

## 使い方

1. 元のゲームプロジェクトの `mines.c` をバックアップします。
2. `autoplay/mines.c` に置き換え、同じディレクトリに `autoplay/visible_solver.h` を配置します。
3. 元プロジェクトの通常の方法でビルドします。
4. ゲームを開始して最初のマスを手動で開き、**Solve** を実行します。

従来の「全答えを表示する Solve」を置き換える実装です。安全と証明したマスだけを通常のゲーム処理で開き、公開された結果を次の推論に使います。結果は通常の開封・旗立てコマンドで盤面に反映されます。

このリポジトリは元ゲーム全体を含みません。単体で GUI アプリを起動することはできません。

## ビルド確認とテスト

C99 対応の C コンパイラが必要です。リポジトリのルートから実行します。

```sh
cd autoplay

# 改造版全体のオブジェクト生成（実行ファイルへのリンクは含みません）
cc -std=c99 -c mines.c -o /tmp/mines-autoplay.o

# 公開情報による推論の検証
cc -std=c99 -Wall -Wextra -Werror test_solver.c -o /tmp/test_visible_solver
/tmp/test_visible_solver

# 元の開封処理を使った結合テスト
cc -std=c99 -Wall -Wextra -Werror test_integration.c -o /tmp/test_mines_integration
/tmp/test_mines_integration
```

確認済みの結果:

- 改造版全体のオブジェクト生成に成功。
- 3×3 の爆弾配置と安全マス公開状態の全組み合わせ **19,683 ケース**で、**25,658 回の推論**が実際の配置と一致。
- 部分集合の差による安全・爆弾判定、曖昧な局面での停止、矛盾の検出に成功。
- 誤った手動の旗を信用しないこと、入力状態を変更しないこと、初手では停止すること、生成コマンドの再生で勝利することを確認。

ゲーム共通処理・グリッド生成・乱数・描画などの実装とビルド設定が未提供のため、実行ファイルのリンクと GUI での動作は未確認です。変形グリッドは最大16隣接の隣接表を利用する設計ですが、各グリッドの実ゲームでの検証は未実施です。
